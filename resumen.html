Los 4 tipos de issue

TipoQué significa
BUG
Reliability		El código hace algo mal hoy. Ej. java:S1206: equals() sin hashCode().
VULNERABILITY
Security		Se puede explotar desde fuera. Se detecta siguiendo el dato hasta el punto peligroso. Ej. java:S2076.
HOTSPOT
Revisión humana		Código sensible. Lo cierra una persona: To Review → Fixed / Safe. Ej. java:S4790: MD5.
Code smell
Maintainability		No falla, pero cuesta mantener. Es la mayoría en cualquier proyecto.

Severidad: Blocker › Critical › Major › Minor › Info. Es el impacto de la regla, no de tu proyecto.

New Code: la idea central

El gate mira solo lo nuevo desde el último análisis. Tu proyecto puede ser un desastre heredado y pasa verde mientras no empeores.

Gate vs Perfil

Quality GateQuality Profile
Las condiciones que cumples. Si una falla → rojo.El conjunto de reglas activas por lenguaje.
Se asocia a cada proyecto.Cambiarlo no cambia el gate.

Sonar way (por defecto)

  • Cero issues nuevos
  • Hotspots nuevos revisados 100 %
  • Cobertura en código nuevo ≥ 80 %
  • Duplicación en código nuevo ≤ 3 %

Cobertura · JaCoCo

Tests¿funciona? → Maven: falla = build parado
Cobertura¿se ejecutó? → cuenta las líneas recorridas
SonarQube¿cumple umbral? → solo lee el XML
No mide que funcione — un test sin afirmaciones da 100 %. Y si un test falla, Maven se para antes: no hay análisis ni informe.

Comando de análisis

cd demo-app
mvn clean verify sonar:sonar `
  "-Dsonar.host.url=TU-SONARQUBE" `
  "-Dsonar.token=squ_XXXXXXXXXXXXXXXXXXX"

Comillas obligatorias en PowerShell — sin ellas la // de la URL parte el argumento.

Orden: compilar → tests → informe → analyzer → servidor evalúa.

La URL y el token nunca van en un fichero. Se pasan por entorno (SONAR_HOST_URL / SONAR_TOKEN) o por -D en el momento.
