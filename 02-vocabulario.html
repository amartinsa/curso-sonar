Vocabulario

Todo lo que encuentra es un issue, y todos los issues son posibles problemas de código de distinto nivel de criticidad que se pueden corregir. Confundirlos es el error más común al empezar.

Bug Reliability

Código probablemente erróneo.

equals() sin hashCode() · posible NullPointerException

Vulnerability Security

Código que puede provocar errores de datos.

Runtime.exec("ping " + host) con entrada del usuario

Security Hotspot Revisión humana

Código que debe revisar un humano: posible error de lógica o no cumple el estándar.

MessageDigest.getInstance("MD5")

Code smell Maintainability

Código difícil de leer o mantener.

tipo == "VIP" en vez de equals() · código que nunca se ejecuta

Severidad: Blocker › Critical › Major › Minor › Info. Es el impacto de la regla, no de tu proyecto.  ·  Deuda técnica: tiempo estimado en arreglarlo.

Cobertura de test

Es el porcentaje de líneas que se ejecutan cuando corren tus tests. JaCoCo escribe el informe; SonarQube solo lo lee.

QuéPreguntaQuién decide
Tests¿funciona?Maven: si falla, el build se para
Cobertura (JaCoCo)¿se ejecutó?Cuenta las líneas recorridas
SonarQube¿cumple el umbral?Solo lee el XML

La cobertura no mide que funcione.

Un test que llama al método y no afirma nada da el 100 %. Y si un test falla, Maven se para antes: no hay análisis ni informe. Mide alcance, no corrección.
