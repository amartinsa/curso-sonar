Cómo se analiza un proyecto

Un solo comando lo pone en marcha.

PS> mvn clean verify sonar:sonar ``
    "-Dsonar.host.url=TU-SONARQUBE" ``
    "-Dsonar.token=squ_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"

Las comillas son obligatorias en PowerShell: sin ellas la // de la URL parte el argumento y Maven no encuentra el plugin.

  1. Compilar y testear

    Si un test falla, Maven se para aquí. No hay análisis. El build es el primer gate.

  2. JaCoCo escribe el informe

    Si no se llega, no existe jacoco.xml y Sonar verá 0 %.

  3. El analyzer revisa el código

    Aplica las reglas activas y monta los hallazgos con su ubicación exacta.

  4. Se envía al servidor

    Con la URL y el token. El token identifica quién analiza: no se guarda en el proyecto.

  5. El servidor guarda y evalúa el gate

    Compara con el análisis anterior para saber qué es nuevo y pinta el resultado.
